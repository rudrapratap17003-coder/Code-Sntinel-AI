# CodeSentinel AI

### See the debt. Understand the risk. Improve the code.

**CodeSentinel AI** is an intelligent repository analysis platform designed to identify technical debt and maintainability risks in software projects.

It analyzes repository structures and source code to uncover patterns such as excessive code complexity, duplicated logic, inconsistent error handling, architectural coupling, and circular dependencies.

The goal is not simply to detect problems, but to make technical debt understandable through explainable findings, measurable indicators, and actionable remediation guidance.

---

## Overview

As software projects grow, technical debt can accumulate through complex functions, duplicated code, tightly coupled modules, and inconsistent coding practices.

These issues may not immediately break an application, but they can make future development, debugging, testing, and maintenance increasingly difficult.

CodeSentinel AI aims to help developers understand these risks by analyzing GitHub repositories and presenting the results through an interactive developer dashboard.

The platform focuses on **evidence-based technical debt analysis**, rather than claiming to prove whether code was written by a human or generated by AI.

## Key Features

### 1. GitHub Repository Analysis

* Submit a supported GitHub repository URL.
* Validate repository links.
* Collect supported source files.
* Exclude unnecessary generated and dependency directories.
* Analyze repository structure and source code.

### 2. Code Complexity Analysis

* Identify functions with high cyclomatic complexity.
* Highlight potentially difficult-to-maintain code.
* Present measurable complexity indicators.
* Provide available source-file evidence.

### 3. Code Duplication Detection

* Identify repeated or similar code blocks.
* Highlight affected files.
* Help developers locate opportunities for refactoring.

### 4. Architectural Dependency Analysis

* Examine relationships between project modules.
* Visualize module dependencies.
* Identify tightly coupled components.
* Highlight detected circular dependencies.

### 5. Code Maintainability Debt Index (CMDI)

CodeSentinel AI uses a project-defined **Code Maintainability Debt Index (CMDI)** to summarize maintainability risks.

The index is intended to provide an understandable overview of technical debt based on measurable analysis indicators.

> CMDI is a project-defined heuristic, not an established universal industry standard.

### 6. Explainable Findings

Each finding can provide available information such as:

* Finding title and description.
* Severity level.
* Category and rule identifier.
* Affected file.
* Line coordinates.
* Supporting evidence.
* Suggested remediation.

### 7. AI-Powered Explanations

Google Gemini integration is intended to help translate technical findings into understandable explanations and practical remediation suggestions.

AI-generated explanations should be grounded in actual static-analysis evidence.

Gemini is an optional enhancement; static analysis should remain usable without it.

### 8. Interactive Dashboard

The React dashboard is designed to provide:

* Repository overview.
* Technical debt indicators.
* Findings explorer.
* Architecture visualization.
* Analysis history.
* Configuration settings.

## Getting Started

Follow these instructions to run the project locally.

### Prerequisites

Install the following:

* Python 3.11 or later (use a version compatible with the project's dependencies).
* Node.js and npm.
* Git.

### 1. Clone the Repository

```bash
git clone https://github.com/rudrapratap17003-coder/Code-Sntinel-AI.git
```

Navigate into the project:

```bash
cd Code-Sntinel-AI
```

### 2. Frontend Setup

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Open the local URL displayed in your terminal, typically:

```text
http://localhost:5173
```

### 3. Backend Setup

Open another terminal in the project root.

Create a virtual environment:

**Windows PowerShell:**

```powershell
py -m venv backend\.venv
```

Activate it:

```powershell
.\backend\.venv\Scripts\Activate.ps1
```

Install backend dependencies:

```powershell
pip install -r backend\requirements.txt
```

Start FastAPI:

```powershell
python -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

The backend should be accessible at:

```text
http://127.0.0.1:8000
```

If configured, interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

Health-check endpoint:

```text
http://127.0.0.1:8000/health
```

## How It Works

The intended repository analysis workflow is:

1. The developer submits a supported GitHub repository URL.
2. The backend validates the repository address.
3. Supported source files are collected.
4. Static analysis examines code complexity, duplication, and dependencies.
5. Findings are generated from available analysis evidence.
6. CMDI is calculated using the project's documented scoring methodology.
7. Architecture information is extracted from actual dependency relationships.
8. Analysis results can be stored for historical access.
9. Gemini can optionally explain findings using the supplied evidence.
10. Results are presented through the React dashboard.

Repository code should be analyzed statically and must never be executed by the analysis service.

---

## Data Integrity and Security

CodeSentinel AI follows several important principles:

* Analysis findings should be supported by actual source-code evidence.
* Missing evidence should not be fabricated.
* Synthetic demonstration data must remain separate from real analysis results.
* CMDI should be presented as a project-defined heuristic.
* AI-generated explanations must not invent technical findings.
* API keys and credentials must remain on the backend.
* Repository code must not be executed during static analysis.
* Unsupported analysis capabilities should be clearly identified.
